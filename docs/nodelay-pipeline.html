Internes Playbook — NoDelay Webdesign, Nic Delley
Betriebshandbuch

Von der Vorlage zur Live-Site — immer gleich, immer nachvollziehbar.

Ein Repo pro Kunde, GitHub als Quelle der Wahrheit, Netlify baut und deployt automatisch. Diese Seite ist der feste Ablauf für jedes neue Projekt und für jede spätere Änderung — zum Abhaken, jedes Mal.

Das System auf einen Blick

Vier Stationen, ein Weg. Code lebt nie nur auf einem Rechner — jede Version ist in GitHub gesichert, jede Änderung geht automatisch live.

Vorlage

Ein geprüftes Startprojekt (z. B. nodelay-webdesign) mit Struktur, Formular-Anbindung und Design-Bausteinen.

Kunden-Repo

Eigenes GitHub-Repository pro Kunde. Jeder Commit ist eine gesicherte Version — das Repo ist gleichzeitig das Backup.

Netlify-Projekt

Mit dem Repo verbunden. Jeder Push löst automatisch npm run build aus und veröffentlicht das Ergebnis.

Live-Domain

Kunden-Domain zeigt auf Netlify, SSL wird automatisch ausgestellt. Für den Kunden sieht man von alldem nichts.

01 · Einmalige Einrichtung

Nur beim allerersten Mal nötig — danach nie wieder.

Konten

GitHub & Netlify

Ein GitHub-Konto für alle Kunden-Repos, ein Netlify-Konto (kostenloser Free-Plan reicht für die meisten Kundenprojekte).

Vorlage

Startprojekt festlegen

Ein bestehendes Projekt (z. B. nodelay-webdesign) als Vorlagen-Repository markieren — GitHub → Settings → „Template repository“.

Werkzeuge

Lokal installiert

Node.js (für npm) und Git müssen lokal installiert sein, um Projekte zu testen, bevor sie live gehen.

02 · Neuer Kunde — Website aufsetzen

Der Ablauf für jedes neue Kundenprojekt, von der Vorlage bis zur Übergabe.

01

Neues Repo aus der Vorlage erstellen (GitHub: „Use this template“) oder klonen und den Git-Verlauf zurücksetzen. Name nach Schema kunde-<firma>.

# Alternative ohne Template-Funktion:
git clone https://github.com/nicdelley-source/nodelay-webdesign.git kunde-mustercafe
cd kunde-mustercafe
rm -rf .git && git init
02

Kundendaten in src/lib/data.js ersetzen (Leistungen, Preise, Portfolio, Kontakt). Farben und Fonts in src/index.css, Logo in src/components/Logo.jsx.

03

Vor dem ersten Push immer im Browser prüfen — Mobile-Ansicht und Kontaktformular nicht vergessen.

npm install
npm run dev
# → http://localhost:5173
04

Neues, leeres Repository auf GitHub anlegen, dann verbinden und den ersten Stand hochladen.

git remote add origin https://github.com/nicdelley-source/kunde-mustercafe.git
git add -A && git commit -m "Erste Version"
git push -u origin main
05

Add new site → Import an existing project → GitHub → Repo auswählen. Build command npm run build, Publish directory dist.

06

Unter Domain settings die Kunden-Domain hinzufügen und die DNS-Einträge beim Registrar des Kunden setzen. Netlify stellt das SSL-Zertifikat automatisch aus — meist innerhalb weniger Minuten.

07

Die Ziel-E-Mail-Adresse im Formular auf die des Kunden anpassen. Bei formsubmit.co bestätigt der Kunde die erste eingehende Mail selbst — oder direkt auf Netlify Forms umstellen (siehe Praxis-Tipps).

08

Kurze schriftliche Zusammenfassung an den Kunden: Live-URL, wie Änderungswünsche gemeldet werden, und ob er als Mitwirkender auf GitHub eingeladen werden möchte.

03 · Änderung für einen bestehenden Kunden liefern

Der wiederkehrende Ablauf, sobald ein Kunde etwas geändert haben möchte.

01

Falls nicht mehr lokal vorhanden: erneut klonen. Sonst den neuesten Stand holen.

git clone https://github.com/nicdelley-source/kunde-mustercafe.git
# oder, falls schon vorhanden:
git pull
02

npm run dev starten, Änderung umsetzen, im Browser gegenprüfen — besonders auf Mobile.

03

Eine klare Commit-Nachricht erleichtert es später, eine bestimmte Änderung wiederzufinden.

git add -A
git commit -m "Preise aktualisiert"
git push
04

Kein manueller Schritt nötig. Im Netlify-Dashboard unter Deploys den Build-Log prüfen — dauert meist unter einer Minute.

05

Auf der echten Domain kontrollieren, nicht nur auf der Netlify-Vorschau-URL — manche Änderungen (z. B. an der Domain-Konfiguration) wirken sich nur dort aus.

04 · Praxis & Regeln

Ein paar Entscheidungen, die sich bei mehreren Kunden gleichzeitig auszahlen.

Struktur

Ein Repo pro Kunde

Nie mehrere Kunden in einem gemeinsamen Repository. So bleibt jedes Projekt unabhängig, eine Änderung bei Kunde A kann Kunde B nie versehentlich betreffen — und ein Repo lässt sich sauber übergeben, falls ein Kunde die Seite später selbst verwaltet.

Namen

Feste Konvention

Repo: kunde-<firma>. Vorläufige Adresse vor eigener Domain: <firma>.netlify.app (in den Netlify-Einstellungen frei wählbar).

Formulare

Netlify Forms statt Drittanbieter

Da ohnehin auf Netlify gehostet wird: netlify als Formular-Attribut ergänzen. Eingebauter Spamschutz, keine fremde E-Mail-Adresse im Quellcode sichtbar, Einträge direkt im Dashboard.

Branches

Vorschau vor „live“

Für grössere Umbauten einen eigenen Branch erstellen. Netlify baut dafür automatisch eine eigene Vorschau-URL (Deploy Preview) — der Kunde kann freigeben, bevor es in main gemerged wird.

Sicherung

Git ist das Backup

Jeder Commit bleibt für immer abrufbar. Bei einem Fehler genügt git log und ein Zurückspringen auf den letzten guten Stand.

Übergabe

Zugriff sauber trennen

Kunde nur dann als GitHub-Collaborator einladen, wenn er selbst Änderungen machen will. Sonst reicht die Live-URL — der Code bleibt vollständig in eigener Verwaltung.

Faustregel: Wenn eine Änderung nur für einen Kunden gilt, gehört sie in dessen Repo — nie in die gemeinsame Vorlage. Verbesserungen, die für alle künftigen Projekte sinnvoll sind, wandern zurück in die Vorlage.

05 · Kurzreferenz

Die Befehle, die in fast jedem Ablauf oben vorkommen — zum Nachschlagen.

Projekt herunterladen & einrichten

git clone <repo-url>
cd <projektordner>
npm install

Lokal ansehen

npm run dev      # Entwicklung, mit Live-Reload
npm run build    # Produktions-Build nach dist/
npm run preview  # Produktions-Build lokal testen

Änderung sichern & veröffentlichen

git status                 # was hat sich geändert?
git add -A
git commit -m "<beschreibung>"
git push                   # → Netlify baut automatisch

Neuesten Stand holen

git pull
